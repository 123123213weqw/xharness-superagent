# 时间兼容边界

固定参考调用 `Date.parse` / `Date.toISOString`，不仅接受 RFC3339。迁移、Trigger 接收、评估截止与恢复判断共用产品 core 的时间实现，不能把无法解析的合法旧时间悄悄当作缺失。

## 当前实现

- ISO 日期/日期时间：缺省月日、显式时区、无时区日期的 UTC 规则、无时区日期时间的本地规则、闰年、日溢出、24:00、毫秒截断及无效值原样保留。
- 兼容参考运行环境 Node 24.9 / V8 13.6 的 legacy 数字日期、月份名、时区名、AM/PM、注释与分隔符语法。语法适配自 V8 13.6.233.10；保留 BSD-3-Clause 版权及许可证于 core 的 NOTICE 和根第三方声明。
- 完整 ECMAScript TimeClip ±8,640,000,000,000,000 毫秒与带符号六位年份；不能用 chrono 较窄的可表示年份范围作为产品范围。
- 歧义本地时间取较早时刻，跳过的墙上时间采用变更前偏移；包含夏令时及日期变更线整天跳过。
- 已知 IANA 时区优先使用锁定 `chrono-tz` 的时区表，避免继承过旧系统 tzdata。`TZ` 未设置时通过 `iana-time-zone` 获取主机配置；无法识别的别名/自定义 POSIX 时区仍走主机 Local 解析。其跨平台、别名和版本差异必须留在 M6 边界验收中，不能从有限差分推导全部兼容。
- 处于 chrono civil 范围之外的日期，按相同 400 年历形分别映射至早期 LMT / 未来规则区间；不把公元前时间错误地映射到现代 DST。`chrono-tz` 的物化表截止 2099，未来仍有周期性 DST 的时区按末期表内的同历形解析，固定尾规则保留固定偏移；跨全部可用 IANA 名称另跑边界矩阵。

## 验证方式

`scripts/superagent/remote-validate.sh time-contracts` 会先同步源码，仅在 WZU_Server 编译。独立 Node oracle 运行 pinned `isoTime`，同一 TZ 启动原生 Rust 二进制，比较 ISO 字符串、毫秒值和错误；不剥离时区、不容忍时间偏差、不调用付费模型。

该测试覆盖 UTC、上海、纽约、阿皮亚、阿姆斯特丹、加德满都、豪勋爵岛与卡萨布兰卡，包含固定反例、结构化矩阵、确定性随机语法及 extended-year 往返。仍需保留原版 Engine、迁移、Store 和全 workspace 回归；组件差分不替代 96 条产品 Rubric。

## 已发现但未关闭

419 个 Node 可用 IANA 名称的 241,344 组边界比较中，仍有 64 组 Asia/Gaza / Asia/Hebron 在 2100 年后不一致。原因是当前同历形映射可能选中含 Ramadan 特例的旧年份，而 V8 的未来规则不再套用该历史特例。必须按真实尾规则解析或更换具有完整未来规则的原生时区实现；不能将这些差异剔除、改 oracle 或计为通过。`time-contracts` 因该严格矩阵保持红灯。
