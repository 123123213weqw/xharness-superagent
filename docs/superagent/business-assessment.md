# 主动研判业务接入

本批是**正式产品路径的离线协议验收子集**，不是全部业务对齐完成。
模型 HTTP/SSE 与 gh 外部服务是明确的 loopback/可执行夹具；正式入口、实际
OpenAI 适配器、Client、Engine、SQLite、Native 会话、CodingToolBundle 和 Outbox
均是真实路径。没有付费模型、真实 GitHub 评论或生产部署。

## 已接入的三个主角色工具

- `orchestrator_eval`：读取当前候选、规则版本、模式、同批事件与关联工单，加载
  有页数/超时上限的来源上下文。正文和窗口有界，其他已加载消息给出短预览；
  原消息全文可按引用补读，不把未读历史标成已完整加载。
- `orchestrator_eval_read`：读取本次评估发现的消息、根/父/线程、仓库文件/目录。
  消息和游标必须来自本次评估；非零 offset 复用先前快照。隐藏路径、
  `node_modules`、路径穿越、伪造引用和结束后的评估会返回错误。GitHub 不提供
  图片读取能力，不伪造图片或附件成功；飞书附件仍待接入。
- `orchestrator_eval_decide`：验证规则覆盖、唯一规则 ID、方向与实现意图、工作目录名
  和确认语，通过现有 `assessment_outcome` 与 `Engine.decide` 落库。没有额外的
  “读过上下文才能决定”新门槛，也没有绕开原策略直接创建 Worker。

主角色现在注册 12/14 个应用工具，Worker 注册 6/6；框架 `skill` 不计入这些数量。
剩余主工具是 `orchestrator_ticket_note` 与 `orchestrator_policy_sync`。
**注册数量不表示所有工具的 PR、后台、飞书和恢复分支均已验收。**

## 已验证的真实业务结果

1. 已授权成员的非点名消息进入推断研判；auto 模式在规则、明确方向与意图证据成立后
   创建推断授权的 Ticket，实际 Worker 写入文件、报告并经 Outbox 回复；重启不重复执行。
2. observe 模式只记录 `would_accept` 和建议，不创建 Worker、工作目录或回复。
   未定设计方向、无匹配规则均记录 ignore 和原业务原因/审计。
3. 缺失/重复规则、缺失意图、超过 100 词的中文确认语、伪造引用与隐藏路径可观察地失败；
   显式请求必须走 route，不能使用 eval 绕开显式路由。
4. 同一 Eval 的批次共享一次初始上下文加载，但每次请求仍按**当前 trigger** 标记原消息、
   选择默认全文。正式测试先结束首个同步启动的单条 Eval，再验证后续真实双消息批次，
   不假设首条 receive 会等待后面的消息。
5. 超时保留“上下文不可用”，不伪造空上下文成功；真正的 gh 子进程被取消并回收。
   SIGINT 中断加载时，子进程结束后才释放状态目录锁，不产生接单或工作目录。

评估完成/替换的 post-commit release 会丢弃缓存并发出取消；关闭过程等待已有读取。
并发政策替换、完整批次/过期重启/缓存失效组合仍需扩展验收，不以接了钩子冒充全覆盖。

## 来源读取与配置

GitHub Issue/PR 会话、行内 review 线程、分支 CI 上下文、仓库路径读取与有界窗口，
另有 20 个直接执行固定原版函数及 Commands 的离线 gh 差分样本。
这不是完整 PR 工单归属或真实外部服务联调的证明。

可选启动字段：`admissionContextMaxPages` 默认 10（1–100）；
`admissionContextTimeoutMs` 默认 15000（1–90000）。尚未接管理 API/UI 的动态更新。

中文/英文确认语上限是产品规则，因此增加 `icu_segmenter = "=2.3.0"`：新增 6 个锁定
外部包，并明确登记 7 个既有包区段的依赖/feature 边；**没有刷新既有版本、来源或 checksum**。
原版 wordCount 的 10 个常见文本/边界样本已直接执行并与 Rust 比较，但不宣称不同 ICU
词典版本在所有文本上等价。这不是 JS/Node 运行时、UTF-16 类型迁移或全语言复刻。
许可证原文及来源哈希保留在根目录第三方通知。严格新增 lock overlay 先还原前一业务
lock，再经过原来的五条 workspace 边审计，固定参考和原内核导入断言不变。

## 验证与边界

详细命令、源代码指纹、本地/远端一致性、完整成功和失败日志，见
[验证记录](../business-assessment-verification.json)。最终在 WZU_Server 独立目录通过
workspace fmt/check/严格 Clippy 与所列 10 个 crate 回归；正式入口共 27 条，其中本批新增 7 条。
组件/旧语言测试、ignored 或能力门控提前返回，不计作产品验收通过。

上一精确提交的 CI 是 macOS 成功、Linux 的 PID 夹具竞态失败：文件创建后写入前被读取。
本批改为原子发布完整 PID，保留原来的进程存活、取消、回收和锁释放断言；不靠放宽断言
或忽略测试变绿。新提交 CI 状态需以其精确 SHA 的运行结果为准。

业务清单仍为 5 组离线通过、9 组部分推进、9 组未运行，不能换算成功能完成率。
两个主工具及完整工具分支、GitHub PR/Review、飞书/多来源、配置 API/UI、后台/停止/
并发、完整崩溃切点与部署备份回退，继续属于同一个活动 Goal。
