## 本批实际修正

### 服务停止信号

正式二进制同时处理 SIGINT/Ctrl-C 与 Unix SIGTERM。两者都取消同一个 owner，
并等待既有 Source、Native、工具及进程关闭；即使信号监听失败，也先等待清理。
没有增加另一套任务执行循环或改变默认沙箱。

新增正式场景证明：

- SIGTERM 中断真实 HTTP/SSE 模型等待，退出为 stopped，释放状态租约并可重开。
- SIGTERM 关闭实际飞书消费者及子孙后才重开；不产生工单、模型请求或回复。

这些不是 systemd 服务安装、机器重启、全部后台任务/SSH 远程子进程的验收。

### 致命来源错误不再被正常循环挂住

普通 CLI 错误仍按原路径重试。owner/SQL/config 读取的致命错误会取消同源兄弟循环、
等待实际 CLI 进程，再使产品组合取消其他来源并退出；不会因主动取消了 consumer
就吞掉导致取消的 monitor 错误，也不会永远等待一个健康来源。

新增正式场景对**一次性测试数据库**注入真实 SQL 故障，验证非零退出、真实消费者
及子孙均已回收；修复测试数据库后重新 --check 可获得租约。测试没有修改现网库。
这只覆盖一处故障切点，不代表全部数据库/来源/恢复矩阵。

## Linux CI 观察竞争的证据

先前2dfb141的 Ubuntu CI 在已有 observed_input 测试失败，Mac 成功。
诊断在独立验证目录复制原测试，只将真实 Store.flush 的调度延迟50ms：
原观察方式稳定复现同一失败；增加有时限的 flush 进展等待后通过。

该测试原来先观察逻辑 TurnEnd，再立即断言随后独立执行的 flush 计数已经增加。
本批只在这两项观察之间加最多5秒等待：**全部原断言逐字保留，任何 Runtime/Core/
Host 实现和默认权限未改，未排除或跳过测试**。仍验证 producer 保持输入时 fsync
可前进、第二条输入未消费且只在 release 后执行一次。不前进仍会超时失败。

新增精确测试 overlay 可反向还原原受控导入字节，三个负向 guard 拒绝弱化断言、
修改等待及修改其他区域。固定216个原版文件、11步/86路径导入链保持；这个本地
测试观察修正单独声明，不伪装成新的上游导入。正常定点另外重复30次通过。

它不是新增产品验收，也不提前保证新精确 head 的跨平台 CI 已通过。

## 冷切不能省略的步骤（历史规程；后续已完成单实例隔离演练）

1. 固定发布源码与二进制，完成准确 head 的 Linux 回归、目标运行权限和实际交付验收。
2. 明确选一个实例及切换边界；确认旧实例的未结束工单可以丢弃续跑，或另行收尾。
3. 停止原实例接入和后台重启来源，等待进程退出，保留完整可恢复快照及原二进制。
4. 新实例必须使用新状态目录；原版 SQLite 相似不代表 DSH 会话可直接由 Native 接管。
5. 为来源游标、重复事件、回复回执及切换前后消息制定并验证重放/截断策略。允许
   丢历史不代表允许旧请求重新执行、重复回复，不能只清空数据库就接相同入口。
6. 新旧不能同时主动消费并回复同一 GitHub/飞书入口；限定名单验证后才扩大流量。
7. 演练失败回退：先停止新入口并处理已发生的外部动作，再恢复旧快照及监督策略；
   不能只换回旧二进制，让两个版本各自重放。

这是切换规程，不是现有可直接执行的 admin 命令；不得假称已有 --migrate/--pause
之类未实现的 CLI。执行生产停止/切换及真实模型/外部写入前须明确操作范围。

  只接受 schema11、无 WAL、无待办 effect、未投递请求、研判队列及未解决回执的快照。

  旧工单、不让旧订阅为新工单授权。导入到私有目录后整体安装，目标已存在就拒绝。
- `python3 scripts/superagent/state-bundle.py snapshot --quiesced --path /绝对路径/状态 --path /绝对路径/配置 --bundle /绝对路径/新备份`：
  服务和重启管理者必须先停止并 join；包含会话、工作区、模式、符号链接及文件摘要。
  WAL/特殊文件、重叠路径、复制期间内容漂移、已有备份都拒绝。
- `verify --bundle ...` 校验全部内容；`restore --quiesced --bundle ... --into /新验证目录`
  做隔离恢复；`restore --quiesced --bundle ... --replace-originals` 在停止状态恢复原路径，
  保留恢复前目录。多对象普通安装失败会回滚已替换对象，不能据此宣称断电/任意切点
  SIGKILL 的恢复事务已经验收。

这两个组件不是自动停服或外部动作对账工具。已接收未完成任务不能靠“允许丢旧会话”
抹掉；已发送回复/PR也不能靠换回旧数据库撤销。正式入口离线回放已验证导入后不再
执行旧事件或重复发送旧回执。真实完整停服/恢复、候选启动、生产切换分开记录。

### 实机演练发现并修复的两处回退问题

1. 静态 SQLite 快照即便以 read-only 打开，也可能在可写备份目录留下 WAL/SHM。
   冷导入现在只对已确认无 WAL 的静止快照使用 `mode=ro&immutable=1`，并新增
   “源数据库字节及辅助文件均不改变”的断言；不把 immutable 用于现网 WAL 数据库。
2. DSH 会扫描会话根目录，恢复前副本放在原目录旁会被当成身份不匹配的会话。
   `restore` 现在把旧目录原子移动到外部隔离区；用可重复的
   `--quarantine-root /同文件系统/私有隔离目录` 指定每个目标文件系统的路径。
   默认为备份父目录；必须在运行时扫描范围之外，并且与对应目标同文件系统，
   缺少匹配路径会在替换前拒绝。不会用跨设备复制伪装原子替换。

真实 canary 经完整备份（8对象/11000文件）、隔离恢复、冷导入、新版占用原端口
但关闭所有接入、受控重启、新版退出、完整原路径恢复及原版 ready。失败轮次和
手动恢复过程保留；不因此宣称六实例已切换、真实流量回退或任意崩溃切点通过。

后续真实 C1、管理 v2、systemd 及完整回退记录见 [最新批次](../business-completion-verification.json)。临时 Mac 代理路线不是服务器独立运行的上线网络方案；环境凭据清理也不是文件凭据隐藏证明。

### CI 不可用不能当“沙箱验证通过”

真实 C1 PR 的 Ubuntu 日志进一步证实，checkout 构建失败的根因是 runner 的
`bwrap --unshare-all` 被拒绝，不是换一个 Python 就完成修复。CI 现在强制实际探测；
仅在失败时安装发行版提供的、针对 `/usr/bin/bwrap` 的 AppArmor userns profile，
重新以非 root 执行相同探测。已有不同 profile 则拒绝覆盖。不关闭全局 AppArmor/
userns 限制，不改 V100，不跳过 checkout 构建断言；新 CI 结果另验。
profile 的权限边界见 [AppArmor 原始配置](https://gitlab.com/apparmor/apparmor/-/blob/master/profiles/apparmor/profiles/extras/bwrap-userns-restrict)。

Mac PR7 另暴露飞书 consumer 重启测试在结果回帖后立即停机，会与 fixture 最后一次
HTTP 响应写入竞争，出现 Broken pipe。只给该测试加“最终请求已完整收到后才停机”
的 barrier；全部 consumer 次数、真实退避时长、Ticket/Trigger/assignment 去重和
HTTP 错误断言保留，不放宽服务错误处理，也不把传输故障统一吞掉。
